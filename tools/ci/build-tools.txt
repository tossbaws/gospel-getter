# The build tools CI downloads from GitHub releases, each pinned by the
# SHA-256 of its release asset. tools/ci/build_tools.py fetches them with the
# workflow's token (gh release download), not anonymously, into a cache keyed
# by these rows, checks every file against its SHA-256 on every run (a cache
# hit too), and lays them out where Trunk and the Tauri bundler look, so they
# never download them themselves. See .github/actions/build-tools.
#
# Each version is set in one place, and a row here only pins its files:
#   trunk         here: the one Trunk version every row of it carries
#   wasm-bindgen  ui-leptos/Cargo.lock (the CLI has to match the crate)
#   wasm-opt      Trunk.toml, [tools] wasm_opt
#   bundler set   TAURI_CLI_VERSION in .github/workflows/dist.yml: its rows
#                 carry that tauri-cli version, and name the files its
#                 tauri-bundler looks for (tauri-bundler's linuxdeploy.rs,
#                 nsis/mod.rs and msi/mod.rs) under its tools folder
#                 (~/.cache/tauri, %LOCALAPPDATA%\tauri)
# A version with no rows here stops the build, saying what to add.
#
# Each SHA-256 here is the one the release publishes (its .sha256 file or
# the asset's GitHub digest); the bundler's NSIS, nsis_tauri_utils and WiX
# also match the SHA-1 and SHA-256 tauri-bundler 2.10.4 pins for them.
# linuxdeploy-plugin-appimage's "continuous" release can be rebuilt
# upstream: then its download no longer matches and the build stops (a
# cached copy still matches), until its new SHA-256 is checked and put here.
#
# install, where the file goes:
#   bin=<member>   that member of the archive, into the tools' bin folder (on PATH)
#   file=<path>    the file itself, at <path> under the bundler's tools folder
#   unzip=<dir>    the zip, unpacked into <dir> under the bundler's tools folder
#   unzip-top=<dir> the zip's one top-level folder, as <dir> there
#
